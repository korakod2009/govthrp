# ระบบลงคะแนนกิจกรรม Roblox

เว็บไซต์ลงคะแนนสำหรับกิจกรรม Roleplay ใน Roblox **The lives of Thai soldiers on the border** มีหน้าผู้สมัคร การค้นหา สถานะกิจกรรม และผลคะแนนจากฐานข้อมูล SQLite ใช้ลงคะแนนในกิจกรรมจริงบนเว็บได้หลังตั้งค่า Discord OAuth และผู้สมัครแล้ว กิจกรรมนี้ไม่ใช่การเลือกตั้งหรือหน่วยงานของรัฐในชีวิตจริง

## สำคัญด้านความปลอดภัย
- การลงคะแนน **ปิดไว้โดยค่าเริ่มต้น** และผู้ดูแลต้องเปิดหรือกำหนดเวลาในแผงควบคุม เพื่อไม่ให้เปิดก่อนเตรียมรายชื่อผู้สมัครและบัญชีผู้ดูแล
- การลงทะเบียนและเข้าสู่ระบบใช้ Discord OAuth2 พร้อม state และ PKCE; ระบบตรวจสอบตัวตนกับ Discord ฝั่งเซิร์ฟเวอร์และไม่รับ Discord ID จากผู้ใช้
- หลังเข้าสู่ระบบ เว็บแสดงรูปโปรไฟล์ Discord โดยดึงรูปจาก CDN ของ Discord; หากไม่มีรูปกำหนดเองจะแสดงรูปเริ่มต้นของ Discord
- ระบบบันทึกคะแนนกำหนด `UNIQUE(voter_id, election_term_id)` ในฐานข้อมูล ดังนั้นบัญชี Discord เดียวกันลงคะแนนได้หนึ่งครั้งต่อสมัย แม้ส่งคำขอซ้ำพร้อมกัน
- หมายเลขผู้สมัครต้องไม่ซ้ำในรายชื่อที่เปิดใช้งาน และนำหมายเลขกลับมาใช้ได้เมื่อปิดใช้งานผู้สมัครเดิม
- ต้องตรวจสอบสิทธิฝั่งเซิร์ฟเวอร์ ไม่ใช่พึ่งปุ่มหรือ JavaScript ในเบราว์เซอร์
- มี session cookie แบบ HttpOnly/SameSite, rate limit, Helmet, audit log และการแยกสิทธิ admin ตาม ID ที่ตั้งค่าไว้
- ไม่มีการสร้างผู้สมัครตัวอย่างอัตโนมัติบนฐานข้อมูลใหม่ ผู้ดูแลต้องเพิ่มรายชื่อจริงของกิจกรรมก่อนเปิดลงคะแนน
- แก้ไขข้อมูลผู้สมัครไม่ได้เมื่อผู้สมัครมีคะแนนแล้ว และการปิดใช้งานผู้สมัครจะไม่ลบคะแนนเดิม

## เริ่มต้น
1. ติดตั้ง Node.js 20 ขึ้นไป
2. แตกไฟล์ ZIP แล้วเปิดเทอร์มินัลในโฟลเดอร์นี้
3. รัน `npm ci` เพื่อติดตั้ง dependency ตาม `package-lock.json`
4. สร้าง Discord Application ใน Discord Developer Portal แล้วเพิ่ม OAuth2 Redirect URL เป็น `http://localhost:3000/auth/discord/callback`
5. คัดลอก `.env.example` เป็น `.env` แล้วตั้ง `SESSION_SECRET` เป็นค่าสุ่มยาวอย่างน้อย 32 ตัวอักษร พร้อมใส่ Discord Client ID, Client Secret และ Discord User ID ของผู้ดูแลใน `ADMIN_DISCORD_IDS` (หลายคนคั่นด้วยเครื่องหมายจุลภาค)
6. รัน `npm start` แล้วเปิด `http://localhost:3000`

เมื่อยังไม่ได้ตั้งค่า Discord OAuth ปุ่มลงทะเบียนจะไม่ทำงาน และ `/auth/discord` จะแจ้งให้ตั้งค่า OAuth ก่อน

## เตรียมโปรเจกต์สำหรับ GitHub
- อัปโหลดเฉพาะ source code และไฟล์ตัวอย่าง `.env.example`; `.gitignore` จะกัน `.env`, dependency, ฐานข้อมูล SQLite, session และรูปผู้สมัครที่อัปโหลดออกจาก Git
- ก่อน push ให้ตรวจรายการไฟล์ที่จะอัปโหลดทุกครั้ง และห้ามใส่ Client Secret, `SESSION_SECRET`, Discord ID ส่วนตัว, คะแนน หรือข้อมูลผู้ใช้ลงใน source code หรือ commit
- หาก secret เคยถูก commit หรือเผยแพร่ ให้เปลี่ยน/ยกเลิก secret นั้นทันที แม้ภายหลังจะลบไฟล์ออกจาก commit แล้วก็ตาม
- เลือกตั้ง repository เป็น Private หาก source code หรือเนื้อหากิจกรรมไม่ควรเผยแพร่สาธารณะ
- เมื่อติดตั้ง Git แล้ว เปิดเทอร์มินัลในโฟลเดอร์โปรเจกต์และตรวจไฟล์ก่อน commit:
  ```sh
  git init
  git add .
  git status --short
  git diff --cached --name-only
  ```
  ตรวจให้แน่ใจว่าไม่มี `.env`, `*.sqlite`, `node_modules` หรือ `public/uploads` แล้วจึง commit และเพิ่ม remote ของ GitHub
- GitHub ใช้เก็บ source code ไม่ใช่ที่รันเว็บ; เมื่อนำไป deploy ให้ตั้ง environment variables บน hosting และใช้ persistent storage สำหรับ `election.sqlite`, `sessions.sqlite` และ `public/uploads` เพื่อรักษาคะแนน session และรูปผู้สมัครเมื่อแอปรีสตาร์ต
- ตั้ง `NODE_ENV=production`, `SESSION_SECRET` แบบสุ่มที่ยาวอย่างน้อย 32 ตัวอักษร และ Discord Redirect URI ให้ตรงกับ HTTPS URL ของเว็บที่ deploy แล้ว
- หาก hosting ไม่มี persistent storage หรือมีหลาย instance อย่าเปิดรับคะแนนจนกว่าจะตั้งค่าฐานข้อมูลและ storage แบบถาวรที่เหมาะสม เพราะไฟล์ SQLite ในเครื่องอาจสูญหายหรือแยกเป็นคนละชุด

หากเข้าสู่ระบบแล้วพบ `invalid_client` ให้ตรวจว่า Client ID และ Client Secret เป็นของ Discord Application เดียวกัน และ Secret เป็นค่าปัจจุบันหลังการ reset โดยแก้ใน `.env` บนเครื่องเซิร์ฟเวอร์แล้วรีสตาร์ตเว็บ ห้ามส่ง Client Secret หรือ SESSION_SECRET ในแชต หากพบ `invalid_grant` ให้เริ่มเข้าสู่ระบบใหม่และตรวจว่า Redirect URI ใน `.env` ตรงกับ Discord Developer Portal ทุกตัวอักษร

หลังผู้ดูแลเข้าสู่ระบบด้วย Discord ที่อยู่ใน `ADMIN_DISCORD_IDS` จะเห็นแผงควบคุมที่ทำได้ดังนี้:
- เปิดหรือปิดการลงคะแนนทันที หรือตั้งเวลาเริ่มและเวลาปิดล่วงหน้า
- เพิ่ม แก้ไข เปิด/ปิดใช้งาน และลบผู้สมัครได้ หมายเลขต้องไม่ซ้ำในรายชื่อที่เปิดใช้งาน และห้ามแก้รายละเอียดผู้สมัครที่เคยมีคะแนน
- อัปโหลดรูปผู้สมัครได้เป็น JPG, PNG หรือ WebP โดยระบบปรับขนาดและบันทึกรูปไว้ใน `public/uploads` จำกัดรูปหลังปรับขนาดไม่เกิน 1.5 MB
- ก่อนบันทึกรูป ให้ลากภาพเพื่อจัดตำแหน่งใบหน้าและใช้แถบซูม; รูปตัวอย่างใช้สัดส่วนเดียวกับการ์ดผู้สมัคร และสามารถปรับครอปรูปเดิมได้ด้วย
- การลบผู้สมัครที่มีคะแนนในประวัติจะปิดใช้งานแทนการลบ เพื่อรักษาความถูกต้องของผลคะแนน ส่วนผู้สมัครที่ไม่มีคะแนนจะถูกลบพร้อมไฟล์รูป
- แก้หัวข้อ รายละเอียด ประกาศ ชื่อกิจกรรม และคำขวัญที่แสดงบนหน้าเว็บ
- ดูจำนวนคะแนน จำนวนผู้สมัคร บัญชี Discord ที่ลงทะเบียน และประวัติเหตุการณ์ผู้ดูแลล่าสุด

การตั้งค่าและเนื้อหาบันทึกใน SQLite จึงคงอยู่หลังรีสตาร์ตเซิร์ฟเวอร์ การเปิดหรือปิดทันทีจะยกเลิกกำหนดเวลาเดิม `ELECTION_OPEN` ใช้กำหนดค่าเริ่มต้นเฉพาะตอนสร้างฐานข้อมูลใหม่เท่านั้น

ฐานข้อมูลเดิมจะถูกย้ายคะแนนที่มีอยู่ไปยังสมัยแรกโดยอัตโนมัติ ผู้สมัครตัวอย่างเริ่มต้นจะถูกนำออกเมื่อยังไม่มีคะแนนผูกอยู่ หากมีคะแนนแล้วระบบจะคงรายการไว้เพื่อรักษาประวัติและปิดใช้งานแทน

ผู้ดูแลเริ่มสมัยการเลือกตั้งใหม่ได้จากหมวด **ตั้งค่าลงคะแนน** การเริ่มสมัยใหม่จะปิดการลงคะแนนและแยกคะแนนออกจากสมัยก่อน ผู้เล่นที่เคยลงคะแนนแล้วจึงมีสิทธิลงคะแนนใหม่ได้หนึ่งครั้งในสมัยใหม่

## ก่อนเปิดรับคะแนนบนเซิร์ฟเวอร์จริง
- ใช้ HTTPS และกำหนด Discord Redirect URI ให้ตรงกับ URL จริงของเซิร์ฟเวอร์
- ใส่ Discord ID ผู้ดูแลที่เชื่อถือได้ใน `ADMIN_DISCORD_IDS` และสำรองฐานข้อมูล `election.sqlite` กับ `sessions.sqlite` อย่างปลอดภัย
- ตรวจสอบรายชื่อผู้สมัคร ช่วงเวลา และประกาศให้ถูกต้องก่อนเปิดรับคะแนน
- Discord OAuth ยืนยันเฉพาะบัญชี Discord ไม่ได้ยืนยัน Roblox User ID; หากต้องจำกัดสิทธิ์ตามบัญชี Roblox ต้องเพิ่มระบบยืนยัน Roblox ก่อน
- ระบบนี้มีไว้สำหรับกิจกรรม Roleplay ไม่ได้มีคุณสมบัติหรือการรับรองสำหรับการเลือกตั้งภาครัฐ
